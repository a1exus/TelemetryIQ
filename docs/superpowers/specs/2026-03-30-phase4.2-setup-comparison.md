# Phase 5: Setup Comparison — Auto-Diff, Session Notes, Session Filtering

## Goal

Enable the "Compare and Improve Car Settings" workflow from the GT7 Data Logger
article. When a driver overlays two laps from different sessions, they should
immediately see what changed — both auto-detected from telemetry and annotated
by the driver.

## Context

GT7 does not export setup files. There is no API, no file, no way to read car
settings programmatically. The GT7 community's de facto standard is phone photos
of the Car Settings screen. TelemetryIQ can do better by auto-detecting changes
from telemetry and providing a fast inline notes field for everything else.

**Design principle:** Auto-detect first, notes second. The tool should do as
much work as possible without user input. Notes fill in what telemetry can't
see.

## Scope

Three pieces, in priority order:

### 1. Auto-Diff Banner (frontend only)

When two laps from **different sessions** are selected for comparison, extract
telemetry values from the first frame of each lap and diff them. Show
differences in a banner between the comparison header and the charts.

**Fields to compare:**

| Field | GT7 Setting | Display |
| --- | --- | --- |
| `gear1`–`gear8` | Transmission gear ratios | "G3: 1.355 → 1.290" |
| `trans_top_speed` | Max speed setting | "Top speed setting: 320 → 340" |
| `calc_max_speed` | Overall calculated top speed | "Calc max speed: 280 → 295" |

These fields are constant per car setup — they do not change across frames
within a lap. Comparing first-frame values is reliable.

**Frontend data plumbing:** Currently `state.lapA` / `state.lapB` store only
`{ id, frames }`. To determine whether two laps are from different sessions,
thread `session_id` through the selection flow:

- In `populateLaps()`, the parent `session` object is already available.
  Attach `session_id` (and `session.notes`) to each `lapWithCar` object.
- In `selectLap()`, store these on `state.lapA` / `state.lapB` alongside
  `id` and `frames`.
- The auto-diff banner and comparison header read `state.lapA.session_id`
  vs `state.lapB.session_id` to decide whether to show.

Rules:
- Only show fields that actually differ (skip identical values).
- Only show when comparing laps from **different sessions** (same session =
  same setup).
- Gear ratios: skip gears where both values are 0 (unused gears).
- Round to 3 decimal places for gear ratios, integers for speeds.
- If nothing differs, don't show the banner.

**No schema change. No API change.** Pure frontend logic using frame data
already fetched.

### 2. Session Notes (schema + API + UI)

#### Schema

```sql
ALTER TABLE sessions ADD COLUMN notes TEXT;
-- PRAGMA user_version = 3
```

Migration paths:
- **Fresh install (version == 0):** `_DDL_SESSIONS` gains `notes TEXT` column.
  Set `user_version = 3`.
- **From v1:** Existing v1→v2 migration runs first (add `track_id`,
  `car_code`, `completed_at`), then v2→v3 migration adds `notes`. Set
  `user_version = 3`.
- **From v2:** `ALTER TABLE sessions ADD COLUMN notes TEXT`. Set
  `user_version = 3`.
- **v3:** Pass (current).

#### API

| Method | Path | Body | Returns |
| --- | --- | --- | --- |
| `PATCH` | `/sessions/{id}` | `{"notes": "front DF +5"}` | `{"ok": true}` |

Edge cases:
- Session ID not found: return `404`.
- Missing `notes` key in body: return `422`.
- `notes` value is `null` or empty string: clear the notes (set to NULL).
- No max length enforced — notes are short labels, not essays. The UI
  truncates display with ellipsis.

`GET /sessions` response gains `notes` field (add `s.notes` to the SELECT).
Update the REST API table in `specs.md` accordingly.

#### UI — Session Browser

Each session row in the `/compare` sidebar gains a notes line:

```
▼ Nürburgring GP                       2026-03-24 14:32
  Porsche 911 GT3 RS · 3 laps · best 1:42.341
  front DF +5, softer rear springs              [edit]
```

- Notes text is shown below the session meta line, truncated with ellipsis if
  longer than the sidebar width.
- If no notes, show a dimmed `[+ add note]` link.
- Clicking `[edit]` or `[+ add note]` replaces the text with an inline
  `<input>` field. Enter or blur saves via `PATCH /sessions/{id}`. Escape
  cancels.
- After save, update the session object in `state.sessions` and re-render
  the row.

#### UI — Comparison Header

When two laps from **different sessions** are selected, show both session notes
above the auto-diff banner:

```
┌──────────────────────────────────────────────────┐
│ A — baseline                                     │
│ B — front DF +5, softer rear springs             │
│                                                  │
│ ⚙ Auto-detected: G3 1.355→1.290, top speed 320→340  │
└──────────────────────────────────────────────────┘
```

- If a session has no notes, show "A — (no notes)" in dimmed text.
- If both laps are from the same session, don't show the header or
  auto-diff banner.

### 3. Session Filtering (frontend only)

Add filter controls to the top of the session browser sidebar:

```
[Track ▾] [Car ▾]
```

Two `<select>` dropdowns populated from the existing session data:
- **Track filter**: "All tracks" + list of unique track names from loaded
  sessions, sorted alphabetically.
- **Car filter**: "All cars" + list of unique car names from loaded sessions,
  sorted alphabetically.

Selecting a filter hides non-matching sessions in the sidebar (CSS
`display: none`, not re-fetch). Both filters can be active simultaneously
(AND logic). Clearing a filter shows all sessions again.

Filters apply to track and car only, **not** to notes text. Notes
search/filtering is out of scope.

**No API change.** Filters operate on the already-loaded `state.sessions`
array. Track/car names resolved from `cars.json` / `tracks.json` already in
memory.

## Out of Scope

- Structured setup fields (dropdowns per setting category) — add later if
  usage warrants it.
- Photo/image attachment to sessions.
- Indirect telemetry detection (tire temps → compound, suspension travel →
  ride height). These are analysis features, not setup identification.
- Lap data export (separate feature).
- Notes search/full-text filtering (future enhancement).
